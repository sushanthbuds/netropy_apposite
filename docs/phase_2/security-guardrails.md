# Security and Safety Guardrails

**Phase:** 2, Task 2-5  
**Status:** Complete

This document defines how the project handles secrets, OpenTofu state, private keys, and destructive operations.

---

## 1. Secret handling

### Never commit

| Item | Why |
|------|-----|
| SSH **private** keys | Full host access |
| AWS access keys / secret keys | Cloud account access |
| ESXi / vCenter passwords | Hypervisor access |
| `.env` files | Often hold tokens and passwords |
| `lab.auto.tfvars.json` | Generated file; embeds SSH **public** key and lab-specific values |

### Allowed in git

| Item | Notes |
|------|-------|
| `config/example-kvm.json` | Uses `ssh_public_key_file` **path** only, not key material |
| SSH **public** keys in docs | Avoid when possible; redact in screenshots |
| `credentials.note` in JSON | Placeholder text only — no real secrets |

### Where to put real credentials

| Platform | Preferred approach |
|----------|-------------------|
| KVM | Local libvirt socket — no remote creds |
| AWS | `AWS_PROFILE`, IAM role, or env vars — **not** in JSON |
| ESXi | Environment variables or a local untracked secrets file |

Example (untracked local file — add path to `.gitignore` if you create one):

```bash
# ~/.config/netropy-lab/secrets.env (never commit)
export AWS_PROFILE=netropy-lab
export VSPHERE_USER=...
export VSPHERE_PASSWORD=...
```

## 2. State files and generated artifacts

OpenTofu **state** records resource IDs, IPs, and sometimes sensitive attributes.

| File / path | Git policy |
|-------------|------------|
| `*.tfstate`, `*.tfstate.*` | **Gitignore** — never commit |
| `.terraform/` | **Gitignore** — provider cache |
| `lab.auto.tfvars.json` | **Gitignore** — generated by CLI or apply script |
| `modules/kvm/.terraform.lock.hcl` | Currently gitignored; may be committed later for reproducible builds (team choice) |

If state is accidentally committed:

1. Remove from git history (mentor guidance).
2. Rotate any exposed credentials.
3. Re-run `tofu apply` to refresh state locally.

## 3. Private keys and JSON config

The JSON contract uses:

```json
"ssh_public_key_file": "~/.ssh/id_ed25519.pub"
```

Rules:

- Point to a **public** key file on the provisioning host.
- **Never** put private key paths or PEM content in JSON.
- The CLI reads the public key at runtime and writes it into generated tfvars (gitignored).

Before commit, run:

```bash
./scripts/check-secrets.sh
```

## 4. Destructive commands

These remove VMs, networks, or cloud resources. Understand impact before running.

| Command | Effect |
|---------|--------|
| `modules/kvm/run-destroy.sh` | Destroys **entire KVM lab** (VMs, networks, pool resources in state) |
| `tofu destroy` | Same — removes all resources tracked in state |
| `virsh destroy <vm>` | Forces power-off of one VM |
| `virsh undefine <vm>` | Removes VM definition from libvirt |
| `sudo ./run-apply.sh` | **Do not run** — breaks `$HOME` and SSH key paths |

### Safeguards implemented

- `run-destroy.sh` requires confirmation (type `destroy`) unless `--yes` or `NETROPY_LAB_CONFIRM_DESTROY=yes`.
- Apply scripts refuse to run as root (`sudo`).
- `AGENTS.md` requires AI assistants to explain destructive commands before suggesting them.

### Safe teardown workflow

```bash
cd ~/netropy-lab/modules/kvm
./run-destroy.sh              # interactive confirmation
# or non-interactive (automation only):
NETROPY_LAB_CONFIRM_DESTROY=yes ./run-destroy.sh
```

## 5. Pre-commit checklist

Before every commit:

- [ ] Run `./scripts/check-secrets.sh`
- [ ] Run `git status` — no `*.tfstate`, `.env`, or `lab.auto.tfvars.json`
- [ ] Review diff for passwords, tokens, or private keys
- [ ] Redact secrets in docs and evidence screenshots

---

## 6. AI assistant rules

See **`AGENTS.md`** and **`.cursor/rules/netropy-lab.mdc`**:

- Do not paste production credentials into chat.
- Do not commit or log secrets.
- Explain destructive commands before execution.
- Redact sensitive values in output.
